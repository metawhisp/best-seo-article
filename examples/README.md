# Annotated run walkthrough

This is the minimum decision trail for a normal Lite article. It is an
illustration of artifact order, not a reusable claim set, ranking forecast, or
permission to publish.

1. Create the run with `init_run.py`; record target, locale, permissions,
   destination, risk, and the requested maximum status.
2. Fill `research/query-decision.md` with one to three candidate queries. Keep
   only the query whose reader job, observed intent, site fit, and evidence
   advantage are clear. If the site already satisfies the job, recommend a
   rewrite instead.
3. Capture `research/serp.json`, open the leading relevant results, and write
   `research/intent-gap.md`: intent, reader stage, minimum answer, actual gap,
   and no-go condition.
4. Write `research/source-plan.md` before prose. Pair each material assertion
   with an authoritative source, volatility note, and fallback.
5. Turn those decisions into `brief.md` and `outline.md`, then draft from the
   ledgers. Add a table, diagram, screenshot, chart, or video only if it makes a
   reader decision easier; otherwise omit it.
6. For Full work, save the first complete draft as `drafts/baseline.md`, repair
   the smallest material reader gap, perform a fact-safe humanization review,
   and write the bound baseline-to-final iteration report.
7. An independent verifier checks each material claim against the actual source.
   An editorial reviewer separately records the six human quality dimensions.
8. Run the validators. A passed validator proves artifact and lifecycle
   mechanics, not that a source is true or an article is useful. Do not create a
   CMS draft or publish until the user separately authorises that mutation.

For a Full run, broaden only the evidence that could change a decision: site
overlap, competitor matrix, first-party proof, internal-link map, source
snapshots, and media/data plan. The complete field-level method is in
`../references/methodology.md`.
